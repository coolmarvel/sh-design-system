# 프로젝트 브리프: sh-design-system

## 한 줄 정의

이성현의 모든 프로젝트가 같은 **클래식 UI/UX(sh-classic)** 를 따르도록, oh-my-design(omd) 레퍼런스와
같은 형식의 `DESIGN.md` + 플랫폼별 토큰 파일 + 눈으로 보는 쇼케이스를 한 저장소에 모은 디자인 시스템 레퍼런스.

## 문제와 사용자

- **문제**: sh-messenger · sh-compositor · sh-econsent · sh-form-designer · sh-web-editor · remote-assist ·
  pdf-editor(-live) · file-converter 등에서 클래식 UI 를 매번 새로 정했다. 프로젝트마다 DESIGN.md 의 베이스
  레퍼런스(Upbit·PACSPLUS 실측·DEXT5 실측 등)와 토큰 값이 달라 결과물이 제각각이다. 규칙·가이드라인이 없으니
  AI 에이전트도 프로젝트마다 다르게 해석한다.
- **사용자 유형**

| 유형 | 이 저장소에서 하는 일 |
|---|---|
| AI 코딩 에이전트 (Claude Code·Codex 등) | 새/기존 프로젝트에서 `DESIGN.md` 를 읽고 그대로 UI 를 만든다. 토큰 파일을 복사해 쓴다 |
| 이성현 (작성자) | 규칙을 고치고, 쇼케이스로 눈으로 확인하고, 새 프로젝트 킥오프 때 레퍼런스로 지정한다 |

## 핵심 시나리오 (v1.0)

1. 에이전트가 새 프로젝트 킥오프에서 Toss 대신 `sh-classic` 을 베이스 레퍼런스로 지정하고, `DESIGN.md` 를 복사해 같은 UI 를 만든다.
2. 에이전트가 프로젝트 스택에 맞는 토큰 파일(CSS 변수·SCSS·Tailwind·JSON·WPF·Avalonia …)을 `dist/` 에서 그대로 가져다 쓴다.
3. 작성자가 토큰 SSOT 한 곳을 고치면 빌드 한 번으로 모든 플랫폼 파일과 `DESIGN.md` 의 토큰 머리말이 함께 갱신된다.
4. 작성자가 쇼케이스(도커 localhost)에서 버튼·툴바·메뉴·탭·표·트리·대화상자 등 부품의 모든 상태를 눈으로 확인한다.
5. 프로젝트별 변형(DEXT5 파란 스킨, PACSPLUS 하늘색, 환자용 터치 크기)은 베이스를 깨지 않는 테마/변형으로 선택해 쓴다.

## 제약

- **플랫폼/형태**: md + JSON 토큰 + 생성 파일 + 정적 HTML 쇼케이스. 서버·DB 없음.
- **범용성**: 특정 스택에 묶이지 않는다. 새 플랫폼은 출력 포맷 하나를 추가해 확장한다.
- **omd 호환**: omd 0.1 레퍼런스 형식(YAML 머리말 + 계약 본문)을 지켜 omd 스킬(`/omd:apply` 등)이 그대로 읽게 한다.
- **기타**: 혼자 쓰는 공개 가능 저장소. 다른 회사 제품의 코드·이미지 자산은 복사하지 않고 수치·배치만 참고한다.

## 기준 프로젝트

- **sh-web-editor + sh-messenger** 가 기준이다 (2026-10-13 사용자 지정). 나머지 프로젝트는 이 둘을 차용했으므로 보조 근거로만 쓴다.
- 결과물 구성은 oh-my-design 빌더의 내보내기와 같다: DESIGN.md · Tailwind v4 · CSS 변수 · DTCG JSON, 그리고 색 팔레트 · 타이포그래피 · 간격·모양 · 부품 · 지침.

## 성공 기준

- 기존 프로젝트들의 클래식 UI 규칙이 하나의 `DESIGN.md` 로 통합되어, 다음 프로젝트부터는 그것만 보고 만든다.
- 토큰 SSOT 를 고치면 모든 플랫폼 파일이 재생성되고, 검증 명령이 동기화 어긋남을 잡아낸다.

## 범위 밖 (이번에 안 하는 것)

- 기존 프로젝트 코드를 이 레퍼런스로 일괄 마이그레이션하는 작업 (각 프로젝트에서 따로 한다).
- React/Avalonia 등 실제 컴포넌트 라이브러리 패키지 배포 (v1 은 계약 + 토큰 + 쇼케이스까지).
- npm 레지스트리 배포. v1 은 GitHub 저장소에서 파일을 가져다 쓴다.
